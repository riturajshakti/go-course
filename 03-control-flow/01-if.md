# 3.1 — if, else, and the if-with-statement Form

## What You'll Learn

- No parentheses around the condition, braces always mandatory, `else` must sit on the closing brace line
- The condition must be strictly `bool` — no truthiness, no assignment-as-expression
- `if v, err := f(); err != nil` scopes `v` across every branch of the chain and nowhere else
- Go has no ternary operator, and the early-return idiom replaces most nesting

## Coming From Another Language

| Other | Go |
|---|---|
| JS `if (x)` with truthy `0`/`""`/`null` | condition must be `bool`; `if 1` is a compile error |
| Python `if items:` on an empty list | `if len(items) > 0` |
| JS/C `if (x = 5)` compiles with a warning | compile error: assignment is not an expression |
| JS `x > 3 ? "a" : "b"` | no ternary at all; use an `if` or a small function |
| Rust `let y = if c { a } else { b }` | `if` is a statement, not an expression |
| JS `if (c) doIt();` | braces are not optional |

## The basic chain

```go
package main

import "fmt"

func classify(n int) string {
  if n < 0 {
    return "negative"
  } else if n == 0 {
    return "zero"
  } else if n < 10 {
    return "small"
  } else {
    return "large"
  }
}

func main() {
  for _, n := range []int{-3, 0, 7, 42} {
    fmt.Println(n, classify(n))
  }
}
```

Output:

```
-3 negative
0 zero
7 small
42 large
```

No parens. Parens are legal around an arbitrary expression — they just do nothing
and `gofmt` leaves them where you put them.

```go
package main

import "fmt"

func main() {
  if (1 + 1) == 2 {
    fmt.Println("parens around the expression are allowed, just pointless")
  }
}
```

Output:

```
parens around the expression are allowed, just pointless
```

## Braces are mandatory and `else` placement is fixed

A one-line body still needs braces.

```go
package main

import "fmt"

func main() {
  x := 5
  if x > 3
    fmt.Println("big")
}
```

This does not compile. Output:

```
# example.com/scratch
./main.go:8:23: syntax error: unexpected newline, expected { after if clause
```

And because Go inserts a semicolon at the end of a line that ends in `}`, `else`
cannot start its own line.

```go
package main

import "fmt"

func main() {
  x := 5
  if x > 3 {
    fmt.Println("big")
  }
  else {
    fmt.Println("small")
  }
}
```

This does not compile. Output:

```
# example.com/scratch
./main.go:10:3: syntax error: unexpected keyword else, expected }
```

`gofmt` will not fix this for you — it is a parse failure, not a formatting one.

## The condition must be bool

There is no truthiness in Go. Not for integers, not for pointers, not for empty
strings or nil slices.

```go
package main

import "fmt"

func main() {
  if 1 {
    fmt.Println("yes")
  }
}
```

This does not compile. Output:

```
# example.com/scratch
./main.go:6:6: non-boolean condition in if statement
```

The same error with a variable:

```go
package main

import "fmt"

func main() {
  x := 1
  if x {
    fmt.Println("yes")
  }
}
```

This does not compile. Output:

```
# example.com/scratch
./main.go:7:6: non-boolean condition in if statement
```

Assignment is a statement, not an expression, so the classic `=`-for-`==` typo is
caught at parse time rather than silently assigning.

```go
package main

import "fmt"

func main() {
  x := 0
  if x = 5 {
    fmt.Println("yes")
  }
}
```

This does not compile. Output:

```
# example.com/scratch
./main.go:7:8: syntax error: cannot use assignment x = 5 as value
```

`gofmt` reports its own version of the same problem before the compiler gets
there: `expected boolean expression, found assignment (missing parentheses around
composite literal?)`.

## The init-statement form

An `if` may carry one simple statement before the condition, separated by a
semicolon. Anything declared there is scoped to the `if` and its `else` branches.

```go
package main

import "fmt"

func main() {
  s := "abc"
  if len(s) > 0 && s[0] == 'a' {
    fmt.Println("starts with a")
  }
  if n := len(s); n > 2 {
    fmt.Println("long", n)
  }
}
```

Output:

```
starts with a
long 3
```

This is overwhelmingly used with a two-result call. `v` is visible in both
branches, including when the error branch wants to report the zero value.

```go
package main

import (
  "fmt"
  "strconv"
)

func main() {
  for _, in := range []string{"42", "x7", ""} {
    if v, err := strconv.Atoi(in); err == nil {
      fmt.Printf("%q -> %d\n", in, v)
    } else {
      fmt.Printf("%q -> error: %v (v is %d)\n", in, err, v)
    }
  }
}
```

Output:

```
"42" -> 42
"x7" -> error: strconv.Atoi: parsing "x7": invalid syntax (v is 0)
"" -> error: strconv.Atoi: parsing "": invalid syntax (v is 0)
```

The scope ends at the closing brace of the last branch.

```go
package main

import (
  "fmt"
  "strconv"
)

func main() {
  if v, err := strconv.Atoi("12"); err != nil {
    fmt.Println("bad")
  } else {
    fmt.Println("good", v)
  }
  fmt.Println(v)
}
```

This does not compile. Output:

```
# example.com/scratch
./main.go:14:15: undefined: v
```

The init statement also works all the way down a chain, and `x` stays in scope
through every `else if`:

```go
package main

import "fmt"

func main() {
  if x := 5; x > 3 {
    fmt.Println("big", x)
  } else if x > 1 {
    fmt.Println("mid", x)
  } else {
    fmt.Println("small", x)
  }
}
```

Output:

```
big 5
```

Idiomatic: use the init form when the value is only needed inside the `if`. If
you need it after, declare it outside with the plain two-line form.

## Early return beats nesting

Both of these are correct. Only one of them scales.

```go
package main

import (
  "errors"
  "fmt"
)

func lookup(k string) (string, error) {
  if k == "" {
    return "", errors.New("empty key")
  }
  return "value:" + k, nil
}

func nested(k string) string {
  v, err := lookup(k)
  if err == nil {
    if len(v) > 3 {
      return v
    } else {
      return "short"
    }
  } else {
    return "err:" + err.Error()
  }
}

func early(k string) string {
  v, err := lookup(k)
  if err != nil {
    return "err:" + err.Error()
  }
  if len(v) <= 3 {
    return "short"
  }
  return v
}

func main() {
  for _, k := range []string{"ab", ""} {
    fmt.Println(nested(k), "|", early(k))
  }
}
```

Output:

```
value:ab | value:ab
err:empty key | err:empty key
```

Idiomatic: handle the error first and return, leaving the happy path unindented
at the bottom of the function. Go code is written this way almost universally,
which is why you rarely see an `else` after a block that returns.

## No ternary

```go
package main

import "fmt"

func main() {
  x := 5
  y := x > 3 ? "big" : "small"
  fmt.Println(y)
}
```

This does not compile. Output:

```
# example.com/scratch
./main.go:7:14: invalid character U+003F '?'
./main.go:7:16: syntax error: unexpected literal "big" at end of statement
```

`?` is not a token in Go at all. Write the four-line `if`, or a one-line helper
if you need it repeatedly. Generics make a `cond[T]` helper possible, but the
community consensus is to just write the `if`.

## Quick Reference

| Form | Notes |
|---|---|
| `if cond { }` | braces required, no parens needed |
| `if cond { } else { }` | `else` on the same line as the closing `}` |
| `if c1 { } else if c2 { } else { }` | no `elif`/`elsif` keyword |
| `if init; cond { }` | one simple statement, then `;`, then the condition |
| `if v, err := f(); err != nil { }` | the dominant idiom; `v` scoped to the chain |
| `if v := f(); v > 0 { } else { use(v) }` | `v` visible in every branch |

| Not in Go | Use instead |
|---|---|
| truthy conditions | an explicit `bool` expression |
| `if (x = 5)` | `if x == 5` |
| ternary `c ? a : b` | a four-line `if`, or a helper func |
| braceless one-liners | braces |
| `else` on its own line | `} else {` |

## Common Mistakes

**Writing `if x {}` where `x` is an int, pointer, or string.** Go has no
truthiness; compare explicitly with `!= 0`, `!= nil`, or `!= ""`.

**Putting `else` on a new line.** Automatic semicolon insertion closes the
statement at the `}`; write `} else {`.

**Using a value declared in an `if` init statement after the chain ends.** Its
scope is the `if`; declare it above the `if` if you need it later.

**Reaching for a ternary.** There isn't one — write the `if`, or extract a small
function.

**Nesting the happy path inside `if err == nil`.** Invert it to
`if err != nil { return ... }` so the success path stays at the left margin.

## Exercises

1. Write `func sign(n int) string` returning `"-"`, `"0"`, or `"+"` using a
   single `if/else if/else` chain, then rewrite it with early returns and no
   `else` at all. Compare line counts.
2. Rewrite `if v, ok := m[k]; ok { ... }` so that `v` is usable after the `if`.
   Explain in one sentence why the init form could not be kept.
3. Take a function with three levels of `if err == nil` nesting and flatten it to
   early returns. Confirm `gofmt -l` reports nothing and the behaviour is
   identical for every input.
4. Try to compile `if ptr {` where `ptr` is a `*int`, and `if s {` where `s` is a
   `string`. Record the exact compiler message for each and note whether it
   differs from the integer case.
5. Write a generic `func pick[T any](c bool, a, b T) T` and use it in place of a
   ternary. Then show one case where it behaves differently from a real ternary
   (hint: both arguments are always evaluated).
