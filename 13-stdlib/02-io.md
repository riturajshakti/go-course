# 13.2 — io: Reader, Writer, and the Helpers

## What You'll Learn

- `Read`'s real contract: `n > 0` can arrive *together with* `io.EOF`, and that bites people
- `io.EOF` is a value you compare against, not an error condition — and how it differs from `ErrUnexpectedEOF`
- The whole helper set: `Copy`, `ReadAll`, `ReadFull`, `TeeReader`, `MultiReader`, `Pipe`, `LimitReader` and friends
- Writing your own `Reader` and `Writer` and dropping them into `io.Copy`

## Coming From Another Language

| Other | Go |
|---|---|
| Node streams (`pipe`, `'data'` events, backpressure) | `io.Reader`/`io.Writer` are **synchronous**; `io.Copy` is the pipe |
| Python `f.read()` returning `""` at EOF | Go returns a distinct `io.EOF` *value*; empty is not the signal |
| Python file objects' many methods | two one-method interfaces, composed |
| Rust `std::io::Read`/`Write` | nearly identical, but EOF is a sentinel error, not `Ok(0)` |
| Rust `read_to_end` | `io.ReadAll(r)` |
| `.pipe(a).pipe(b)` chains | wrap: `io.TeeReader(io.LimitReader(r, n), log)` |

`io.Reader` and `io.Writer` are the two most important interfaces in Go, and their power
is entirely a consequence of being one method wide. A `*os.File`, a TCP connection, a gzip
decompressor, an HTTP request body, a `strings.Reader` and a `bytes.Buffer` are all the
same type as far as any function that takes an `io.Reader` is concerned, so a compression,
hashing or rate-limiting layer is just a wrapper that also has a `Read` method. The catch
that trips newcomers is the `Read` contract: it is allowed to return fewer bytes than you
asked for, and it is allowed to return data *and* `io.EOF` in the same call. Code that
checks the error before using `n` loses the last chunk of every such stream. See 5.6 for
these interfaces in the wider context of Go's stdlib interface conventions.

## The two interfaces

```go
type Reader interface {
  Read(p []byte) (n int, err error)
}

type Writer interface {
  Write(p []byte) (n int, err error)
}
```

`Read` fills `p` and reports how many bytes it wrote into it. It never allocates, never
resizes `p`, and reading into a zero-length `p` is allowed and returns `0, nil`.

`Write` must write all of `p` or return an error — a short write without an error is a
contract violation, and `io.Copy` reports it as `io.ErrShortWrite`.

## Read's contract and the EOF subtlety

The rule from the docs: callers should always process the `n > 0` bytes returned **before**
considering the error.

```go
package main

import (
  "fmt"
  "io"
  "strings"
)

type eofWithData struct {
  s    string
  done bool
}

func (r *eofWithData) Read(p []byte) (int, error) {
  if r.done {
    return 0, io.EOF
  }
  r.done = true
  n := copy(p, r.s)
  return n, io.EOF
}

func drain(label string, r io.Reader) {
  buf := make([]byte, 4)
  for i := 0; i < 5; i++ {
    n, err := r.Read(buf)
    fmt.Printf("%s read %d: n=%d err=%v data=%q\n", label, i, n, err, buf[:n])
    if err != nil {
      break
    }
  }
}

func main() {
  drain("strings.Reader", strings.NewReader("hello!"))
  fmt.Println()
  drain("eofWithData", &eofWithData{s: "hi"})
  fmt.Println()

  sr := strings.NewReader("")
  n, err := sr.Read(make([]byte, 4))
  fmt.Printf("empty reader: n=%d err=%v\n", n, err)

  zero, err := strings.NewReader("abc").Read(nil)
  fmt.Printf("zero-length buf: n=%d err=%v\n", zero, err)

  fmt.Println("EOF is a sentinel:", io.EOF.Error())
  fmt.Println("ErrUnexpectedEOF:", io.ErrUnexpectedEOF.Error())
}
```

Output:

```
strings.Reader read 0: n=4 err=<nil> data="hell"
strings.Reader read 1: n=2 err=<nil> data="o!"
strings.Reader read 2: n=0 err=EOF data=""

eofWithData read 0: n=2 err=EOF data="hi"

empty reader: n=0 err=EOF
zero-length buf: n=0 err=<nil>
EOF is a sentinel: EOF
ErrUnexpectedEOF: unexpected EOF
```

`strings.Reader` is polite: it returns the data, then `0, io.EOF` on a separate call. But
`eofWithData` returns `n=2` *and* `io.EOF` in one call, and that is entirely legal. The
broken loop is the obvious one:

```go
for {
  n, err := r.Read(buf)
  if err != nil {
    break
  }
  process(buf[:n])
}
```

That drops `"hi"` completely. The correct shape always handles `n` first:

```go
package main

import (
  "errors"
  "fmt"
  "io"
  "strings"
)

type eofWithData struct {
  s    string
  done bool
}

func (r *eofWithData) Read(p []byte) (int, error) {
  if r.done {
    return 0, io.EOF
  }
  r.done = true
  n := copy(p, r.s)
  return n, io.EOF
}

func readCorrectly(r io.Reader) (string, error) {
  var out []byte
  buf := make([]byte, 4)
  for {
    n, err := r.Read(buf)
    out = append(out, buf[:n]...)
    if err != nil {
      if errors.Is(err, io.EOF) {
        return string(out), nil
      }
      return string(out), err
    }
  }
}

func main() {
  s, err := readCorrectly(&eofWithData{s: "hi"})
  fmt.Printf("correct loop:  %q err=%v\n", s, err)
  s, err = readCorrectly(strings.NewReader("hello!"))
  fmt.Printf("correct loop:  %q err=%v\n", s, err)
}
```

Output:

```
correct loop:  "hi" err=<nil>
correct loop:  "hello!" err=<nil>
```

Idiomatic: do not write this loop. Call `io.ReadAll`, `io.Copy`, `io.ReadFull` or a
`bufio.Scanner` (13.3) — they all get the contract right. Write `Read` loops only when
implementing a `Reader` yourself.

### io.EOF is expected; io.ErrUnexpectedEOF is not

`io.EOF` means "the stream ended where a stream may legally end". `io.ErrUnexpectedEOF`
means "the stream ended in the middle of something that needed more bytes". The helpers
pick between them for you.

| Sentinel | Meaning |
|---|---|
| `io.EOF` | clean end of input; compare with `==` or `errors.Is` |
| `io.ErrUnexpectedEOF` | EOF after a partial read that needed to be complete |
| `io.ErrShortWrite` | a `Write` returned `n < len(p)` with a nil error |
| `io.ErrShortBuffer` | the supplied buffer was too small for the operation |
| `io.ErrClosedPipe` | read or write on a closed `io.Pipe` end |
| `io.ErrNoProgress` | a `Reader` returned `0, nil` too many times in a row |

`io.EOF` is never wrapped by the stdlib readers, so `err == io.EOF` works — but
`errors.Is(err, io.EOF)` is the habit to keep, since your own layers may wrap it.

## Copying and reading

| Function | Signature | Returns / note |
|---|---|---|
| `Copy` | `(dst Writer, src Reader) (int64, error)` | until EOF; EOF is **not** an error |
| `CopyN` | `(dst Writer, src Reader, n int64) (int64, error)` | `io.EOF` if the source is shorter |
| `CopyBuffer` | `(dst Writer, src Reader, buf []byte) (int64, error)` | reuse a buffer; `nil` buf allocates |
| `ReadAll` | `(r Reader) ([]byte, error)` | never returns `io.EOF`; unbounded memory |
| `ReadFull` | `(r Reader, buf []byte) (int, error)` | `EOF` if nothing read, `ErrUnexpectedEOF` if partial |
| `ReadAtLeast` | `(r Reader, buf []byte, min int) (int, error)` | same error split at `min` |
| `WriteString` | `(w Writer, s string) (int, error)` | uses `WriteString` if `w` has it |
| `Discard` | `var Discard Writer` | `/dev/null`; implements `ReaderFrom` |

```go
package main

import (
  "bytes"
  "fmt"
  "io"
  "strings"
)

func main() {
  var dst bytes.Buffer
  n, err := io.Copy(&dst, strings.NewReader("copy me"))
  fmt.Printf("Copy: n=%d err=%v out=%q\n", n, err, dst.String())

  dst.Reset()
  n, err = io.CopyN(&dst, strings.NewReader("abcdefgh"), 3)
  fmt.Printf("CopyN(3): n=%d err=%v out=%q\n", n, err, dst.String())

  dst.Reset()
  n, err = io.CopyN(&dst, strings.NewReader("ab"), 5)
  fmt.Printf("CopyN(5) short: n=%d err=%v out=%q\n", n, err, dst.String())

  dst.Reset()
  n, err = io.CopyBuffer(&dst, strings.NewReader("buffered"), make([]byte, 2))
  fmt.Printf("CopyBuffer: n=%d err=%v out=%q\n", n, err, dst.String())

  data, err := io.ReadAll(strings.NewReader("read it all"))
  fmt.Printf("ReadAll: %q err=%v\n", data, err)
  data, err = io.ReadAll(strings.NewReader(""))
  fmt.Printf("ReadAll empty: %q len=%d err=%v\n", data, len(data), err)

  buf := make([]byte, 5)
  m, err := io.ReadFull(strings.NewReader("abcdefgh"), buf)
  fmt.Printf("ReadFull ok: n=%d err=%v %q\n", m, err, buf[:m])
  m, err = io.ReadFull(strings.NewReader("abc"), buf)
  fmt.Printf("ReadFull short: n=%d err=%v %q\n", m, err, buf[:m])
  m, err = io.ReadFull(strings.NewReader(""), buf)
  fmt.Printf("ReadFull empty: n=%d err=%v\n", m, err)

  m, err = io.ReadAtLeast(strings.NewReader("abcdefgh"), buf, 2)
  fmt.Printf("ReadAtLeast(2): n=%d err=%v %q\n", m, err, buf[:m])
  m, err = io.ReadAtLeast(strings.NewReader("a"), buf, 3)
  fmt.Printf("ReadAtLeast short: n=%d err=%v\n", m, err)

  dst.Reset()
  m, err = io.WriteString(&dst, "via WriteString")
  fmt.Printf("WriteString: n=%d err=%v out=%q\n", m, err, dst.String())

  n, err = io.Copy(io.Discard, strings.NewReader("thrown away"))
  fmt.Printf("Discard: n=%d err=%v\n", n, err)
}
```

Output:

```
Copy: n=7 err=<nil> out="copy me"
CopyN(3): n=3 err=<nil> out="abc"
CopyN(5) short: n=2 err=EOF out="ab"
CopyBuffer: n=8 err=<nil> out="buffered"
ReadAll: "read it all" err=<nil>
ReadAll empty: "" len=0 err=<nil>
ReadFull ok: n=5 err=<nil> "abcde"
ReadFull short: n=3 err=unexpected EOF "abc"
ReadFull empty: n=0 err=EOF
ReadAtLeast(2): n=5 err=<nil> "abcde"
ReadAtLeast short: n=1 err=unexpected EOF
WriteString: n=15 err=<nil> out="via WriteString"
Discard: n=11 err=<nil>
```

Read the three `ReadFull` lines together — they are the whole EOF/ErrUnexpectedEOF
distinction in one place. Nothing read at all gives `io.EOF`; a partial fill gives
`io.ErrUnexpectedEOF`. `ReadAtLeast(buf, 2)` returned 5, not 2: `min` is a floor, not a
cap, and it fills the buffer when it can.

`io.Copy` returns `nil` at end of stream — it swallows `io.EOF` deliberately, because
"copied everything" is success. `io.CopyN` does not: falling short of `n` is a failure.

`ReadFull(r, buf)` is the right call whenever a format says "the next 4 bytes are a
length prefix". `ReadAll` on a network body is how services get OOM-killed — bound it
with `io.LimitReader` first.

## Composition helpers

| Function | Signature | Does |
|---|---|---|
| `MultiReader` | `(readers ...Reader) Reader` | concatenates; EOF only after the last |
| `MultiWriter` | `(writers ...Writer) Writer` | writes to all; stops at the first error |
| `TeeReader` | `(r Reader, w Writer) Reader` | every byte read is also written to `w` |
| `LimitReader` | `(r Reader, n int64) Reader` | EOF after `n` bytes; no error if shorter |
| `NewSectionReader` | `(r ReaderAt, off, n int64) *SectionReader` | a seekable window |
| `NopCloser` | `(r Reader) ReadCloser` | adds a no-op `Close` |
| `Pipe` | `() (*PipeReader, *PipeWriter)` | in-memory synchronous pipe |

```go
package main

import (
  "bytes"
  "crypto/sha256"
  "fmt"
  "io"
  "os"
  "strings"
)

func main() {
  fmt.Println("--- MultiReader ---")
  mr := io.MultiReader(
    strings.NewReader("one "),
    strings.NewReader("two "),
    bytes.NewReader([]byte("three")),
  )
  all, _ := io.ReadAll(mr)
  fmt.Printf("%q\n", all)

  fmt.Println("--- MultiWriter ---")
  var a, b bytes.Buffer
  mw := io.MultiWriter(&a, &b, os.Stdout)
  fmt.Fprintln(mw, "to three places")
  fmt.Printf("a=%q b=%q\n", a.String(), b.String())

  fmt.Println("--- TeeReader ---")
  var seen bytes.Buffer
  tee := io.TeeReader(strings.NewReader("payload"), &seen)
  h := sha256.New()
  io.Copy(h, tee)
  fmt.Printf("consumed=%q sha=%x\n", seen.String(), h.Sum(nil)[:8])

  fmt.Println("--- LimitReader ---")
  lr := io.LimitReader(strings.NewReader("abcdefghij"), 4)
  got, err := io.ReadAll(lr)
  fmt.Printf("%q err=%v\n", got, err)
  got, err = io.ReadAll(io.LimitReader(strings.NewReader("ab"), 10))
  fmt.Printf("under limit: %q err=%v\n", got, err)

  fmt.Println("--- SectionReader ---")
  sr := io.NewSectionReader(strings.NewReader("0123456789"), 3, 4)
  got, _ = io.ReadAll(sr)
  fmt.Printf("section(3,4)=%q size=%d\n", got, sr.Size())
  sr.Seek(1, io.SeekStart)
  got, _ = io.ReadAll(sr)
  fmt.Printf("after Seek(1): %q\n", got)

  fmt.Println("--- NopCloser ---")
  rc := io.NopCloser(strings.NewReader("x"))
  fmt.Printf("%T Close=%v\n", rc, rc.Close())

  fmt.Println("--- Seek whence ---")
  s := strings.NewReader("0123456789")
  for _, w := range []struct {
    name   string
    off    int64
    whence int
  }{
    {"SeekStart", 2, io.SeekStart},
    {"SeekCurrent", 3, io.SeekCurrent},
    {"SeekEnd", -2, io.SeekEnd},
  } {
    pos, err := s.Seek(w.off, w.whence)
    fmt.Printf("%-12s off=%+d -> pos=%d err=%v\n", w.name, w.off, pos, err)
  }
  fmt.Println("constants:", io.SeekStart, io.SeekCurrent, io.SeekEnd)
}
```

Output:

```
--- MultiReader ---
"one two three"
--- MultiWriter ---
to three places
a="to three places\n" b="to three places\n"
--- TeeReader ---
consumed="payload" sha=239f59ed55e737c7
--- LimitReader ---
"abcd" err=<nil>
under limit: "ab" err=<nil>
--- SectionReader ---
section(3,4)="3456" size=4
after Seek(1): "456"
--- NopCloser ---
io.nopCloserWriterTo Close=<nil>
--- Seek whence ---
SeekStart    off=+2 -> pos=2 err=<nil>
SeekCurrent  off=+3 -> pos=5 err=<nil>
SeekEnd      off=-2 -> pos=8 err=<nil>
constants: 0 1 2
```

`TeeReader` is the hash-while-you-upload pattern: the hasher sees every byte without a
second pass and without buffering the payload.

`LimitReader` under its limit is not an error — it simply ends early. So it cannot tell
you whether the input was truncated; if you need to detect "longer than allowed", read
`n+1` bytes and check the length.

Note the `%T` of `NopCloser`: `io.nopCloserWriterTo`, not a plain `nopCloser`. Because
`*strings.Reader` has a `WriteTo` method, `NopCloser` returns a wrapper that forwards it,
keeping the `io.Copy` fast path intact.

`SeekEnd` with a negative offset is how you read a file's tail. `Seek` past the end is
legal and does not error — it creates a hole on the next write.

## io.Pipe

`io.Pipe` connects a `Writer` to a `Reader` in memory with no buffer at all: each `Write`
blocks until a `Read` consumes it. It is the adapter for "this API wants a `Reader` but my
code produces output by writing".

```go
package main

import (
  "errors"
  "fmt"
  "io"
)

func main() {
  pr, pw := io.Pipe()
  go func() {
    fmt.Fprint(pw, "streamed through a pipe")
    pw.Close()
  }()
  got, err := io.ReadAll(pr)
  fmt.Printf("pipe: %q err=%v\n", got, err)

  pr2, pw2 := io.Pipe()
  go func() {
    pw2.Write([]byte("partial"))
    pw2.CloseWithError(errors.New("upstream failed"))
  }()
  got, err = io.ReadAll(pr2)
  fmt.Printf("CloseWithError: %q err=%v\n", got, err)

  pr3, pw3 := io.Pipe()
  pr3.Close()
  n, err := pw3.Write([]byte("nobody home"))
  fmt.Printf("write to closed-read pipe: n=%d err=%v\n", n, err)
  fmt.Println("is ErrClosedPipe:", errors.Is(err, io.ErrClosedPipe))

  pr4, pw4 := io.Pipe()
  pw4.Close()
  buf := make([]byte, 4)
  n, err = pr4.Read(buf)
  fmt.Printf("read from closed-write pipe: n=%d err=%v\n", n, err)

  fmt.Println("ErrShortWrite:", io.ErrShortWrite)
  fmt.Println("ErrClosedPipe:", io.ErrClosedPipe)
  fmt.Println("ErrNoProgress:", io.ErrNoProgress)
}
```

Output:

```
pipe: "streamed through a pipe" err=<nil>
CloseWithError: "partial" err=upstream failed
write to closed-read pipe: n=0 err=io: read/write on closed pipe
read from closed-write pipe: n=0 err=EOF
ErrShortWrite: short write
ErrClosedPipe: io: read/write on closed pipe
ErrNoProgress: multiple Read calls return no data or error
```

The writer goroutine is mandatory. Writing to a pipe from the same goroutine that reads it
deadlocks instantly, because the write cannot complete until a read happens.

`CloseWithError` is the only way to tell the reader that production failed — closing
normally would look like a clean EOF, and the consumer would happily accept a truncated
stream. Always `CloseWithError(err)` on the producer's error path.

`*os.File` is the everything type — it is why file code composes so freely. `*bytes.Buffer`
is a `Reader` *and* a `Writer`, which makes it the default test double for both halves.
`ReaderAt` is the interesting one: it takes an absolute offset and does not touch a shared
position, so it is the only read method safe to call concurrently on the same value.

### The io.Copy fast path

`io.Copy` checks whether `src` implements `WriterTo` or `dst` implements `ReaderFrom`, and
if so delegates entirely, skipping its own 32KB buffer. That is observable:

```go
package main

import (
  "bytes"
  "fmt"
  "io"
  "strings"
)

type plainWriter struct {
  calls int
  n     int
}

func (p *plainWriter) Write(b []byte) (int, error) {
  p.calls++
  p.n += len(b)
  return len(b), nil
}

type plainReader struct {
  r     io.Reader
  calls int
}

func (p *plainReader) Read(b []byte) (int, error) {
  p.calls++
  return p.r.Read(b)
}

type shortWriter struct{}

func (shortWriter) Write(b []byte) (int, error) {
  if len(b) > 3 {
    return 3, nil
  }
  return len(b), nil
}

func main() {
  src := strings.Repeat("x", 100000)

  pw := &plainWriter{}
  io.Copy(pw, strings.NewReader(src))
  fmt.Printf("plain writer, WriterTo source: writes=%d bytes=%d\n", pw.calls, pw.n)

  pw2 := &plainWriter{}
  io.Copy(pw2, &plainReader{r: strings.NewReader(src)})
  fmt.Printf("plain writer, plain source:    writes=%d bytes=%d\n", pw2.calls, pw2.n)

  pr := &plainReader{r: strings.NewReader(src)}
  var buf bytes.Buffer
  io.Copy(&buf, pr)
  fmt.Printf("ReaderFrom dest, plain source: reads=%d len=%d\n", pr.calls, buf.Len())

  n, err := io.Copy(shortWriter{}, strings.NewReader("abcdefgh"))
  fmt.Printf("short writer: n=%d err=%v\n", n, err)
  fmt.Println("is ErrShortWrite:", err == io.ErrShortWrite)
}
```

Output:

```
plain writer, WriterTo source: writes=1 bytes=100000
plain writer, plain source:    writes=4 bytes=100000
ReaderFrom dest, plain source: reads=10 len=100000
short writer: n=3 err=short write
is ErrShortWrite: true
```

100,000 bytes went out in **one** `Write` when the source had `WriteTo`, versus four
32KB-chunk writes when it did not. The practical consequence: wrapping a reader in your own
struct can silently remove a fast path, because your wrapper does not forward `WriteTo`.

The last case is `io.ErrShortWrite`: `shortWriter` claimed to write 3 of 8 bytes with a
nil error, which violates the `Writer` contract, and `io.Copy` turns that into an error
rather than silently losing data.

## Implementing Reader and Writer

Both are one method. A `Reader` wrapper reads from its source into the caller's buffer and
transforms in place; a `Writer` wrapper transforms and forwards.

```go
package main

import (
  "fmt"
  "io"
  "os"
  "strings"
)

type upperReader struct {
  r io.Reader
}

func (u upperReader) Read(p []byte) (int, error) {
  n, err := u.r.Read(p)
  for i := 0; i < n; i++ {
    if p[i] >= 'a' && p[i] <= 'z' {
      p[i] = p[i] - 'a' + 'A'
    }
  }
  return n, err
}

type countingWriter struct {
  w      io.Writer
  bytes  int64
  writes int
}

func (c *countingWriter) Write(p []byte) (int, error) {
  n, err := c.w.Write(p)
  c.bytes += int64(n)
  c.writes++
  return n, err
}

type prefixWriter struct {
  w       io.Writer
  prefix  []byte
  atStart bool
}

func newPrefixWriter(w io.Writer, prefix string) *prefixWriter {
  return &prefixWriter{w: w, prefix: []byte(prefix), atStart: true}
}

func (p *prefixWriter) Write(b []byte) (int, error) {
  written := 0
  for _, c := range b {
    if p.atStart {
      if _, err := p.w.Write(p.prefix); err != nil {
        return written, err
      }
      p.atStart = false
    }
    if _, err := p.w.Write([]byte{c}); err != nil {
      return written, err
    }
    written++
    if c == '\n' {
      p.atStart = true
    }
  }
  return written, nil
}

func main() {
  src := strings.NewReader("hello io\nsecond line\n")
  counter := &countingWriter{w: newPrefixWriter(os.Stdout, "| ")}

  n, err := io.Copy(counter, upperReader{r: src})
  fmt.Printf("Copy n=%d err=%v\n", n, err)
  fmt.Printf("counter: bytes=%d writes=%d\n", counter.bytes, counter.writes)

  var sb strings.Builder
  io.Copy(&sb, upperReader{r: strings.NewReader("mixed Case 123 ünïcode")})
  fmt.Println(sb.String())
}
```

Output:

```
| HELLO IO
| SECOND LINE
Copy n=21 err=<nil>
counter: bytes=21 writes=1
MIXED CASE 123 üNïCODE
```

Three things this demonstrates.

The whole chain is `strings.Reader -> upperReader -> countingWriter -> prefixWriter ->
os.Stdout`, assembled with ordinary struct literals and glued by one `io.Copy`.

`upperReader` must return `n` and `err` unchanged from its source, including the
data-plus-EOF case — transforming in place is the only safe thing to do when the
transformation does not change the byte count. A length-changing transform (gzip, base64,
UTF-16) cannot be written this way; it needs its own internal buffer, which is what
`bufio` and `encoding/base64`'s wrappers provide.

The last line shows the honest limitation: upper-casing byte by byte leaves `ü` and `ï`
untouched, because they are multi-byte UTF-8 and their bytes are not in `a`..`z`. Correct
case mapping across a `Read` boundary needs rune buffering — see 6.8.

Idiomatic: `Write` must report the number of bytes of `p` it consumed, not the number it
wrote downstream. `prefixWriter` writes more bytes than it was given, and still returns
`written` counted over `b`.

## Quick Reference

| Need | Call |
|---|---|
| Read a whole stream | `io.ReadAll(r)` |
| Read a whole stream, bounded | `io.ReadAll(io.LimitReader(r, max))` |
| Stream to a destination | `io.Copy(dst, src)` |
| Copy exactly n bytes | `io.CopyN(dst, src, n)` |
| Fill a fixed-size buffer | `io.ReadFull(r, buf)` |
| Throw output away | `io.Copy(io.Discard, r)` |
| Hash while streaming | `io.TeeReader(r, hasher)` |
| Write to two places | `io.MultiWriter(a, b)` |
| Concatenate streams | `io.MultiReader(a, b)` |
| Cap how much is read | `io.LimitReader(r, n)` |
| A window on a file | `io.NewSectionReader(f, off, n)` |
| Satisfy a `ReadCloser` | `io.NopCloser(r)` |
| Turn a writer into a reader | `io.Pipe()` + a producer goroutine |
| Seek to the tail | `f.Seek(-n, io.SeekEnd)` |
| Clean end of input | `errors.Is(err, io.EOF)` |
| Truncated input | `errors.Is(err, io.ErrUnexpectedEOF)` |

| Trap | Reality |
|---|---|
| `if err != nil { break }` before using `n` | loses data when `n > 0` arrives with `io.EOF` |
| Treating `io.EOF` from `io.Copy` as a failure | `Copy` returns `nil` at end of stream |
| `io.ReadAll` on a request body | unbounded; wrap in `LimitReader` |
| `LimitReader` to detect truncation | under-limit input is not an error |
| Writing to an `io.Pipe` without a goroutine | immediate deadlock |
| `pw.Close()` on the producer's error path | the consumer sees a clean EOF and trusts a partial stream |
| Wrapping a reader "transparently" | you drop its `WriteTo`, and the `io.Copy` fast path |
| `Read` into a shrunk buffer | it fills `len(p)`, not `cap(p)` |

## Common Mistakes

**Checking the error before processing `n` bytes.** A legal `Reader` may return data and
`io.EOF` together; handle `buf[:n]` first, always.

**Calling `io.ReadAll` on anything you did not produce.** Wrap it in
`io.LimitReader(r, maxBytes)` so a large input cannot exhaust memory.

**Closing an `io.Pipe` writer normally after a failure.** Use `CloseWithError` so the
reader sees the error instead of a clean EOF on truncated data.

**Returning a short count from `Write` with a nil error.** That breaks the contract;
`io.Copy` will turn it into `io.ErrShortWrite`.

**Expecting `io.Copy` to flush a `bufio.Writer`.** `Copy` returning nil means the bytes
reached the writer, not the device — you still must `Flush` (13.3).
